## コンセプト

デスクトップの隅に常駐するドット絵キャラが、タスクを放置すると勝手にサボり始めるToDoアプリ。

面白さの中心は**時間**にある。キャラはユーザーを見張る監督ではなく、隣に住む同居人。タスクを片づけるたびに褒めてくれて、放置が続くと自分がだれ始め、寝転がったりスマホをいじったりして、最後は先に力尽きて寝る。

実用性はオマケと割り切る。優先順位は「くだらなさ」と「見てて楽しい」。ToDo機能は追加と完了があれば足りる。完了したタスクは自動的に削除する。

キャラの姿は、縮小時はペット、全画面時は人間アバター。既定は縮小で、ペットだけで作品は成立するため、ペットを先に仕上げて人間アバターは後回しにする。性格、セリフ、ポーズは[キャラクター設定書](02-character.md)にまとめている。

## デスクトップアプリとしての運用

このアプリは常駐して初めて成立する。ウィンドウを閉じたら消えるキャラは、サボっているところを見てもらえない。ユーザーが別の作業をしている間も、視界の端に居座り続ける必要がある。

## スコープ

C++とSDLを必須の技術と決めたため、**2Dに限定**する。

3Dにすると、モデルの読み込みから関節の動きまで自前で作ることになり、キャラが動き出す前に時間を使い切る。2Dなら、使う道具が絵の表示まで面倒を見てくれる。

### 初版でやること

- 背景が透明で、常に手前に表示される小さなウィンドウ（パネルは半透明）
- 場面ごとに切り替わるドット絵キャラ（ペット1体）の表示
- ToDoの追加・完了（完了したタスクは自動的に削除）
- 経過時間によるサボり進行
- 吹き出しによるセリフ
- ドラッグによる移動

### やらないこと

- 3Dモデル（絵は2Dのドット絵だけ）
- クラウド同期、アカウント機能
- Windows以外への対応（macOS、Linux、モバイル）
- 複数キャラの同時常駐

## コア仕様：サボり進行

材料は「未完了タスクの有無」と「最後に操作してからの経過時間」。操作はタスクの追加と完了の2つを指す。操作への反応を除けば、この2つで今の場面が決まる。場面ごとのセリフとポーズは[キャラクター設定書](02-character.md)を参照する。

### 場面の進行

```mermaid
stateDiagram-v2
    direction LR
    [*] --> 起動直後
    起動直後 --> 待機 : 3秒後（未完了あり）
    起動直後 --> タスク0個 : 3秒後（未完了なし）
    待機 --> 溜めたまま放置 : 一定時間操作なし
    溜めたまま放置 --> 長時間放置 : さらに時間が経つ
    待機 --> 操作への反応 : タスク操作
    溜めたまま放置 --> 操作への反応 : タスク操作
    長時間放置 --> 操作への反応 : タスク操作
    タスク0個 --> 操作への反応 : タスク追加
    操作への反応 --> 待機 : 表示時間が終わる（未完了あり）
    操作への反応 --> タスク0個 : 表示時間が終わる（未完了なし）
```

> 図は本文の説明と設定書から起こしたもの。「操作への反応」は、1つ完了、複数完了、全部完了、追加、追加（5個以上）の総称。放置の各場面へ進む秒数は未定（等速だと寝るまで約3分）。

### 実装ルール

| 項目 | 方針 | 理由 |
|---|---|---|
| 段階を進める秒数 | 判定を1か所にまとめて書く | 数字を変えたくなったとき、そこだけ直せば済む |
| 操作への反応 | 「いつまでそのポーズか」の時刻を記録して毎フレーム判定する | 一定時間で元に戻す作りだと、連続でタスクを片づけたときにポーズが競合する |
| 完了場面の優先順位 | 全部完了を複数完了より優先する | 残りが0になった瞬間は、全部終わったことへの反応を見せる |
| セリフ | 場面ごとの辞書として1か所にまとめる。ユーザーの怠惰を指摘するセリフは足さない。タスク0個と長時間放置は無言 | キャラを変えるときは辞書を差し替えるだけで済み、性格もぶれない |
| 開発中の時間 | 10倍速にして試す | 等速だと寝るまで3分かかり、動作確認が面倒になって確認しなくなる |

## 難しくなりそうなところ

初版はWindowsだけを対象にする。手こずりそうなのは次の3つで、どれもOSの作りに踏み込む必要があり、既成の機能で済ませられない。

| 課題 | 内容 |
|---|---|
| ペットの背後をクリックできるようにする | 透明な部分でクリックを受け止めてしまうと、下にあるアプリが操作できなくなる。既成の機能がないので自分で用意する |
| ほかのアプリを使っている間のキー入力を知る | 打鍵に反応させるために要る。Windowsには仕組みがあるが、常に受け取り続ける作りにする必要がある |
| 配布 | 実行ファイルをそのまま渡せる。ただし署名がないと初回起動時に警告が出るので、渡す相手には一言添える |

1つめは、使う予定の道具（SDL）の側でも[未解決の課題](https://github.com/libsdl-org/SDL/issues/12683)として議論が残っている段階。自分で用意する前提で見ておく。

3つとも必須ではない。時間だけでサボる挙動なら無くても成立するので、詰まったら後回しでよい。

## マイルストーン

フェーズAの4つが終わった時点で「デスクトップに住んでサボるキャラ」として成立する。5以降は無くても成立するので、詰まったら後回しでよい。

### フェーズA ― まず動かす

| # | やること | 完了条件 |
|---|---|---|
| 1 | 透過ウィンドウに四角を描く | デスクトップに四角が浮かび、枠もタスクバーアイコンも出ない |
| 2 | ドラッグで移動できるようにする | 掴んで動かせて、離した位置に留まる |
| 3 | サボり進行の場面判定を実装する | タスク操作と放置に応じて、四角の色が場面ごとに変わる |
| 4 | スプライトシートで四角を置き換える | ドット絵がぼけずに表示され、場面ごとに切り替わる |

### フェーズB ― 常駐らしくする

| # | やること | 完了条件 |
|---|---|---|
| 5 | グローバル入力フックを入れる | 他のアプリを操作中でも打鍵を検知できる |
| 6 | クリックスルーとトレイ常駐 | キャラの背後をクリックでき、トレイから終了できる |
| 7 | 配布できる形にする | 別のWindows機で起動する |

最初の関門は1番。ここが通れば残りは地続きになる。ToDo機能の実装は3番と並行でよく、単独のマイルストーンには置かない。

## 設計方針

- **見た目の切り替えは1か所にまとめる**
  ほかの部分はポーズの名前を渡すだけにして、四角からドット絵への差し替えがそこだけで済むようにする。
- **サボり方のルールは見た目から切り離す**
  先にプレースホルダの四角で挙動を完成させ、絵は後から差し込む。この順序なら、絵が未完成でもサボり方を詰められる。逆に絵を先に描くと、ポーズを減らしたくなったときに描いた分が無駄になる。
- **ドット絵はAsepriteで作り、1枚のスプライトシートに書き出す**
  状態ごとのフレームを横並びにする。切り出し矩形の計算が単純になり、フレームの追加にも耐える。
- **キャラのサイズは16の倍数にそろえる**
  ペットは64×48を基準にする。整数倍で拡大するとにじまない。

## 将来の拡張

初版が動いてから検討する。どれも初版の完成を待たずに手をつけると、常駐の基礎が固まる前に発散する。

| 機能 | 内容 |
|---|---|
| キー入力連動 | 打鍵中は待機のまま、手が止まると放置の場面へ進む。デスクトップアプリだから作れる機能で、最も効果が大きい |
| やる気ゲージ | 未完了タスクが多いほど進行が速くなる。溜めるほど早くサボる |
| 人間アバターと全画面表示 | 全画面時の姿とレイアウト。ペットが全ポーズ動いてから着手する |
| キャラの選択 | セリフ辞書と絵を差し替えて性格を変える。1体目が完成してから考える |
| 効果音 | 打鍵音、あくび。SDL3の音声機能で足りる |

### 初版後も検討しないもの

クラウド同期、3D化、Live2D対応の3つは、スコープの線引きを壊すため初版後も検討しない。
